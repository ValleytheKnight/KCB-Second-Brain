# KnightOS Milestone 1 Task 3: single tab, real terminal, shipped and verified

Built Task 3 of KnightOS's Milestone 1: the real terminal. React scaffolds the renderer via electron-vite's react plugin, resolving the framework choice deferred since Task 1 (decision 6e6c18ae), decided as React after presenting Chris a real comparison (decision 510aabff). xterm.js renders on top of Task 2's proven node-pty foundation with a capped 5,000-line scrollback. The main process now opens a real folder via a native directory picker and spawns the terminal cwd'd there on demand, replacing the single startup-bound shell Tasks 1-2 used. An env-gated bypass (KNIGHTOS_E2E_FOLDER) stands in for the native picker during automated verification, since a native OS dialog has no DOM to drive.  Verified live end to end via CDP against the real running app, not just build/typecheck: real folder binding, real ANSI-colored git log output, real keystroke round trip, real resize confirmed against the actual OS console width (PowerShell's own $Host.UI.RawUI.WindowSize read stale and misled the first check; [Console]::WindowWidth confirmed the real value), and real scrollback (confirmed via genuine CDP Input-domain mouse wheel events after synthetic in-page WheelEvent dispatch failed to register with xterm 6's internal handler). Also tried launching the real `claude` CLI inside the embedded terminal; it hit a pre-existing PowerShell execution-policy restriction on this machine, confirmed unrelated to KnightOS by reasoning about how a real standalone PowerShell window would behave identically, not a bug to fix here. Added a real Playwright E2E test (e2e/terminal.spec.ts) automating the same open-folder-type-command-see-output flow, 1/1 passing alongside 18/18 Vitest and a clean typecheck.  A real mistake happened mid-build and was caught before landing: the empty first-launch state's mark was built by copying inline SVG markup directly out of the locked mockup HTML file and treating it as the real logo. Chris caught it live ("devknight is using the wrong logo"). Investigation traced it to the mockup's own placeholder illustration, added late during plan-design-review with no real logo asset checked against, and confirmed the actual approved logo pick (Assets/KnightOS/logo-interim-chatgpt.png, from 6 ChatGPT-generated options) had never itself been decision-logged, only narrated in vault prose, so there was no real record to catch the mismatch against. Fixed by copying the real PNG into the app's own asset path and rendering it directly; the fix landed in the same Task 3 commit, nothing wrong ever reached a push. The logo pick itself is now decision-logged (08a5e49f). DevKnight's own definition was patched with two new standing rules as a direct result: never pull literal content out of a mockup file, even a locked one, only from decision_search or the vault's actual approved Design records; and do a full unprompted project orientation before resuming real work on a project already touched this session, not gated behind Chris saying "execute project X."  Committed as 38cabda (design/product/TODO docs that were sitting untracked) and cdb5925 (Task 3's full build), both pushed to github.com/ValleytheKnight/KnightOS. Vault synced in the same session: 00 Overview.md's Continuation Point rewritten, Milestone 1 Kanban's Task 3 card moved to Done with full evidence, Projects/_index.md's one-liner updated, DESIGN.md's provisional-values note updated to point at the now-real styles.css.
