# KnightOS Phase 1 Task 2 implemented: tear-off proof-of-concept, go/no-go passed

Implemented the tear-off proof-of-concept at C:\Users\Chris Brown\Documents\DevPrograms\KnightOS. New main-process state: `src/main/pane-host-registry.ts` (PaneHostRegistry, canonical paneId-to-windowId map, debounced ~75ms broadcast, last-write-wins by construction since Node's event loop serializes every IPC handler) and `src/main/window-registry.ts` (windowId-to-BrowserWindow map). `src/main/index.ts` wires these in: TerminalManager's onOutput now routes through `windowRegistry.get(paneHostRegistry.hostOf(paneId))` instead of a hardcoded mainWindow, and createTornOffWindow() opens a real second BrowserWindow loading the same renderer bundle with query params rather than a second Vite entry point.  Handoff protocol, to guarantee no dropped live output: main creates the torn-off window but does NOT flip paneHostRegistry immediately. The new window's own TornOffWindow.tsx component (src/renderer/src/TornOffWindow.tsx) subscribes to terminal output first, then sends PaneTornOffReady; only on receiving that does main call setHost, completing the handoff. Until then, output keeps flowing to the main window, whose own pre-existing backgroundOutputBuffers safety net (built for Project Tabs Task D) covers any window where the TerminalPane happens to have already unmounted.  New IPC surface (src/shared/ipc.ts, src/preload/api.ts): PaneTearOff, PaneReDock, PaneTornOffReady, PaneHostChanged, exposed as named preload functions (paneWindow.tearOff/reDock/signalReady/onHostChanged) per the Electron security checklist, payload validated both directions (isTearOffPayload, isPaneHostState in src/shared/pane-host.ts).  App.tsx subscribes to onHostChanged and unmounts its own TerminalPane for any pane currently hosted elsewhere, exactly mirroring the existing backgrounded-Project pattern, so only one renderer ever owns a given pane's live pty at a time. Deliberate scope cut: a torn-off window starts blank, no scrollback replay across the process boundary, only live-output continuity is required by the acceptance criteria and is what's proven. Full scrollback handoff deferred to Task 11.  Verification: test/pane-host-registry.test.ts (8 unit tests covering last-write-wins, debounced broadcast, releaseWindow). e2e/tear-off.spec.ts drives the real app via Playwright's Electron support: tears off a live pane, types into the new OS window, types concurrently with a main-window resize, redocks, verifies output resumes in the main window. Had to fix two real issues found only by running this for real: (1) the torn-off window's header sat behind the xterm surface due to absolutely-positioned stacking, fixed with z-index; (2) Playwright's `Page.waitForEvent('close')` never fires for a window closed from the main process side (BrowserWindow#close), confirmed via main-process disk logging that the window did close correctly, worked around with `expect.poll(() => page.isClosed())`.  A real regression was also found and fixed: adding the tear-off icon into ShopRail's channel tag broke e2e/multi-tab.spec.ts (switching tabs silently stopped working after the second switch). Root cause: `label-row`'s `justify-content: space-between` distributed three children (label, tear-off, close) such that the new icon landed near the row's horizontal center, exactly where Playwright's (and a real user's) default click lands. Fixed by grouping the tear-off and close icons together in their own flex group and giving the label real `flex: 1 1 auto`.  Full verification after the fix: typecheck clean, 199/199 Vitest, 47/47 Playwright e2e passing in isolation (one worker-teardown flake seen only when running all 47 serially in one worker over 9 minutes, reproduced as a pass when run in isolation, an infra flake not a regression).  Spec's Task 2 acceptance/verification checkboxes and go/no-go result recorded at Projects/KnightOS/01 Planning/Phase 1 Multi-Window System Feature Spec.md.
