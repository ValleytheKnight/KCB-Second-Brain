# Obsidian protocol: bounded Session Resume rewrite plus a hygiene-gate false-positive fix

Investigated why the Obsidian agent's activation protocol was expensive to run: every "activate obsidian" read five files in full (Rules.md 304 lines, Lessons.md 480 lines, Ideas Backlog.md 886 lines, Shipped and Roadmaps.md 862 lines, and Protocol Obsidian.md itself at 1557 lines). The last one was the real problem: its Session Resume section was a pure append-only chronological log, never pruned, growing on every "deactivate obsidian" since 2026-07-23. Reading it during this investigation blew past a single Read call's 25000-token cap and needed a second call to finish, concrete proof the growth was already causing real friction, not just a theoretical concern.  Root cause: Session Resume was never designed as a rolling snapshot the way loremaster's own Continuation Point is (that file's own protocol explicitly says "replace it, never append, it is a rolling snapshot rather than a history"). Protocol Obsidian.md had no equivalent discipline, so every session's full narrative (what was tested, what broke, what got fixed) accumulated in place forever. Later checkpoints in the file were already calling dev_diary_log/learnings_log for some of this content, meaning the typed home for it already existed and was already partly in use, the append-only file was duplicating it in an unindexed, unbounded second location.  Fix: moved the full existing history verbatim into a new archive file, Protocol Obsidian Session History Archive.md (nothing lost), then rewrote Session Resume as three lean per-thread blocks (Homebrewery v3 port, Linked Text Styles, Anchor Flow), each with State/Next action/Blocked-on, replaced in place rather than appended to. Updated both trigger sections in Protocol Obsidian.md: "deactivate obsidian" now routes session narrative to dev_diary_log/decision_log/learnings_log and rewrites the relevant thread's block in place; "activate obsidian" documents Session Resume as a bounded snapshot rather than a log to read historically. Mirrored the same discipline into the registered agent definition via update_agent (never a hand-edit, per the one-path rule), covering the First Action section and the "How to work with Chris" section's deactivation bullet.  A design idea considered and dropped: caching Rules.md/Lessons.md/Ideas Backlog.md/Shipped and Roadmaps.md behind a Mnemosyne semantic-recall digest to skip re-reading them when unchanged. Rejected because Rules.md and Lessons.md are load-bearing (hygiene gates, API gotchas that prevent real bugs), and a lossy digest standing in for them on every activation would reintroduce exactly the failure mode loremaster's and devknight's own full-orientation protocols exist to prevent. Logged as decision (confidence 8, repo scope).  Separate bug found and fixed while writing the archive file: the pretooluse-hygiene-gate.ts hook's COMMENT_LINE regex (hosts/claude/hooks/pretooluse-hygiene-gate.ts) treated any line starting with a bare `*` as a code-comment continuation line (intended for JSDoc-style ` * @param foo` lines), which also matches Markdown's `**bold**` convention at the start of a line, a pattern this project's own historical prose uses constantly ("**Test #7... is Passed...**"). This falsely triggered the dev-diary-comment-pattern (ISO date) check against ordinary bold Markdown text. Confirmed narrow and safe to fix: changed the bare `\*` alternative to `\*(?!\*)` (a negative lookahead excluding the immediately-doubled-asterisk case), which still matches a real single-asterisk comment continuation but no longer matches `**bold**`. Verified only one copy of this pattern exists in the repo (grepped for COMMENT_LINE and dev_diary_comment_patterns). This was a real false positive discovered through actual use, not a guess, since the same dated content already lived unblocked in the pre-existing Protocol Obsidian.md.
