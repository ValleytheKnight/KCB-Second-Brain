# omarchy-theme-forge: Task 2 (safe_join guard) done, dangling-symlink bug found and fixed across two review rounds

Built Task 2 only, per explicit instruction: a standalone, unit-tested safe_join path-traversal guard at src-tauri/src/theme_path.rs (+ theme_path/tests.rs), modeled on tauri-dev's safe_join pattern, closing the HIGH security-review finding (decision 2f1cb4fd) that omarchy-theme-from-image only lowercases and dash-normalizes a theme name, never rejects a traversal attempt.  Full orientation first: read the Task 2 spec from the task breakdown, decision_search/dev_diary_search for prior omarchy-theme-forge context (confirmed the project's real state: Task 1 scaffold done under the renamed repo, knightbrain_omarchy-theme-forge graph live but still only indexing README.md, no code yet), read tauri-dev's safe_join reference pattern directly rather than reasoning from memory, and confirmed on disk that no theme_path module existed yet.  Implementation: safe_join(base, raw_name) rejects empty, null byte, '/', '\', and leading '.' before any normalization runs (covers leading '/', leading '.', '../' sequences, and Windows-style backslash sequences as one rejection each), then applies the same lowercase+dash normalization as the real script, then resolves the joined path against a canonicalized base with a bounds check.  Two full /simplify (4 parallel review agents each) + /code-review rounds ran per Chris's standing instruction, one per commit that changed code.  Round 1 found and fixed: a real, PoC-confirmed dangling-symlink escape. The original implementation treated "canonicalize() failed with NotFound" as "nothing here yet, safe to leave unresolved," but a dangling symlink's target also resolves to NotFound, so a planted dangling symlink at base/evil returned Ok(base/evil) unresolved and uncanonicalized, which a later fs::write following that path would have followed straight through the symlink to wherever it pointed, outside base entirely. Fixed by disambiguating with symlink_metadata (lstat, does not follow) before deciding. Also applied 3 simplify findings: switched test temp-dir handling from a hand-rolled, leaking helper to tempfile::tempdir() (a real leak the reuse review caught), collapsed a redundant exists()+canonicalize() double-syscall into one canonicalize() call, and shared a canonicalize-error-formatting helper between the two call sites. Added a regression test replicating the exact PoC.  Round 2 (over round 1's own fix) found 3 more real gaps, all fixed: the doc comment claimed the bounds-check runs for a dangling symlink when canonicalize() actually short-circuits before that line; a dangling target and an unrelated environmental I/O error (permission denied, a symlink loop) both fell into the same generic Io variant with no way for a future caller to tell an attempted escape from a benign hiccup; and the existing-target path paid for both a symlink_metadata and a canonicalize syscall where one suffices in the common case. Fixed by reordering to try canonicalize() first (one syscall in the common existing-target case), falling back to symlink_metadata only to disambiguate a NotFound result, and giving a dangling/unresolvable target its own ThemeNameError::UnresolvableTarget variant distinct from generic Io. Added a symlink-loop regression test alongside the corrected dangling-symlink one.  3 findings from round 2 were surfaced and deliberately not fixed, flagged here rather than silently dropped: (1) a TOCTOU window between the path-safety check and whatever a future caller does with the returned path, real but dormant since no command calls safe_join yet in this diff, a design question for whichever of Tasks 6/10/11/14 wires it in first, not Task 2's own scope; (2) and (3) were test-style nits (tempdir() call-site duplication, one test binding a variable others inline) judged low-value/false-positive given tempfile::tempdir() is already a one-line call, not the kind of multi-line duplication that earns a wrapper.  Final state: 13 unit tests, all passing (cargo test), covering every traversal vector the dispatch named (leading '/', leading '.', '../' sequences, symlink escape, null bytes, Windows-style backslashes) plus the two real gaps the review process surfaced (dangling symlink, symlink loop). cargo build clean except the two expected "never used" warnings for safe_join/io_err/ThemeNameError, since Task 2 explicitly builds this as an isolated module with no command wired to it yet; that wiring is Tasks 6, 10, 11, 14's job.  Committed in 3 commits (1752d1f initial module, 3b15878 dangling-symlink fix, dcbde72 UnresolvableTarget variant + canonicalize-first reorder) and pushed to origin/master.
