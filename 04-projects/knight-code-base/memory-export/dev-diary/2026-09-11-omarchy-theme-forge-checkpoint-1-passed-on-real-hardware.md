Two environment facts worth keeping. omarchy resolves at /usr/bin/omarchy for Chris's login shell but at /usr/share/omarchy/bin/omarchy for the agent's environment; both are real and the check handles either, so this is not a defect, but it means a hardcoded path anywhere in this app would be wrong. The app's Linux window class is "app", inherited from the Cargo package name, and a packaged build would rename the binary to productName, so the class differs between cargo tauri dev and an installed package. The Hyprland opacity opt-out was therefore written to match the window title rather than the class, since the title is identical in both builds.
