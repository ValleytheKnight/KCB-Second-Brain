# KnightOS Milestone 1 Task 5: tab-close confirmation, shipped and verified

Resumed KnightOS this session on Chris's explicit go-ahead past Task 4's pause. Full orientation ran first: Continuation Point, Milestone 1 Kanban, Task Breakdown, the Design folder's README, and a fresh on-disk check, since a /simplify pass had landed on top of Tasks 1-4 since the last touch (commit 6d1f50f) and needed re-verifying against real state rather than trusted from memory. Confirmed clean: 19/19 Vitest, typecheck clean, 3 commits ahead of origin/master.  Built Task 5: closing a tab with nothing running still closes immediately; closing a tab with a real running foreground process now prompts first, cancel keeps the tab and process alive, confirm kills the process and closes the tab. Detection asks Windows directly which processes have the tab's real shell PID as their parent (Get-CimInstance Win32_Process -Filter "ParentProcessId=..."), since node-pty's own .process getter is only genuinely live on its Unix backend, confirmed by reading node-pty's own source (WindowsTerminal.process just returns a static launch string on the ConPTY backend this app uses). Fails closed on an unanswerable query, so a real process is never silently killed. Prefers pwsh.exe over powershell.exe for the check itself since this runs on every close attempt and pwsh starts materially faster.  A fast concept mockup (an Artifact, built from only the forge/workshop system's already-locked tokens, no new visual direction) was reviewed before the real CloseConfirmDialog component was written, per the standing design-workflow rule that the mockup step runs even for small changes, rather than treating a two-button dialog as too small to need one.  Verified live via Playwright against the real built app: a genuine long-lived foreground child process (ping -t, not a shell builtin) triggers the prompt; cancel and confirm both work correctly; an idle tab still closes with no prompt. Non-Windows platforms are an honest, tracked gap (TODOS.md), not a silent guess, since KnightOS targets Windows only today. Committed d90f3b8.  A /simplify pass ran immediately after, per Chris's standing instruction that a task isn't done until it's had one. 4 reviewers (reuse, simplification, efficiency, altitude) found 5 dedup'd issues, applied 4: generalized TerminalManager's private withTerminal guard to return a value instead of hasActiveProcess duplicating it; extracted one shellExe() helper instead of two copies of the same pwsh/powershell ternary; factored a shared openSingleTab() e2e helper; and a real robustness fix, not just tidiness, an in-flight Set guard so a rapid double-click can't fire two concurrent process checks for the same tab (the efficiency and altitude reviewers independently flagged the same underlying gap from two angles). Skipped one finding with reason: lowering per-check PowerShell spawn latency via a native process-tree call or a persistent piped process is real engineering beyond a tidy pass.  That pass also caught a real regression: the async close flow it introduced exposed a genuine race in the pre-existing Task 4 multi-tab e2e spec, two close clicks fired back to back with no wait now landed before the first close resolved, closing the same tab twice instead of two different tabs. Fixed by waiting for the tab count to actually drop between clicks, and the general lesson (check anything downstream that assumed old synchronous timing whenever a change makes something async) is recorded in the vault's own Lessons Learned note for this project.  Verified clean across repeated full runs, not once: typecheck, 21/21 Vitest, and all 4 Playwright e2e specs (including the pre-existing Task 3/4 ones) passing across 2 consecutive full runs under real 3-worker concurrency. Confirmed no stray ping.exe/shell/Electron processes left running after test runs. Committed 950b349.  Vault synced in the same session: 00 Overview.md's Continuation Point rewritten, Milestone 1 Kanban's Task 4 and Task 5 cards moved to Done with full evidence plus a new Task-5-quality-pass Done entry, the milestone-level KnightOS Project Kanban's stale "security checklist not yet built" backlog item corrected to Done (it was already written and just never reflected there), Projects/_index.md's one-liner updated, and a new 06 Lessons Learned note plus its README index entry added for Task 5's simplify pass and the e2e race it caught.
