# Scryptable: fifth code-review pass, persisted a verification that had only been ad hoc, closed a branch-coverage gap

Fifth follow-up in the same session to the Import-dropdown-menu contrast fix chain (`0fac271`, `ef9cade`, `07544ea`, `e6ee468`, `04fb19c`). Ran `/code-review` a fifth time against `04fb19c` per this repo's standing rule.  Two real findings, both about the fourth fix's own new tests, not the app code:  1. The `_declared()` collision fix (`background-color` vs `color`) was verified ad hoc in a throwaway one-off script the previous round and never committed as an actual test, despite the prior commit message claiming it was "confirmed." Nothing in the file would have caught a future regression back to plain substring matching. Added a permanent `test_declared_does_not_match_inside_a_longer_hyphenated_property_name` test.  2. `test_effective_background_falls_through_item_rule_before_menu_rule` only covered `item_rule` missing a background declaration entirely, never `item_rule` explicitly declaring `"transparent"`, a separate, completely untested branch. Replaced the single test with a parametrized `test_effective_background_cascade_matches_qt` covering all six meaningful branches of the cascade: the rule's own real value, fallthrough to `item_rule`, fallthrough all the way to `menu_rule`, and `"transparent"` at either level correctly not stopping the fallthrough.  Verified both by reproducing the exact regression each new test is meant to catch: ran the old buggy `_declared()` against the collision case (wrong value returned, confirming the new test would fail on a reversion) and ran a broken cascade missing the item-level transparent check (returned the literal string `"transparent"` instead of falling through, confirming the new parametrized case would fail too).  Committed and pushed as `0115c29` to `https://github.com/ValleytheKnight/Scryptable` (master). 153/153 tests pass. A sixth `/code-review` pass is running to check whether this chain has finally converged.  Updated the DevKnight Workshop vault: a sixth follow-up subsection in `Projects/Scryptable/06 Lessons Learned/Task 7 Diarization Integration Build Notes.md`, and a significantly compressed `00 Overview.md` Continuation Point bullet and `Projects/_index.md` one-liner, both now summarizing the real shape of this six-commit chain (one real app-visible fix, five successive review passes catching defects only in the test's own code) rather than repeating the full blow-by-blow inline, since the full detail already lives in the Lessons Learned note and these dev-diary entries.
