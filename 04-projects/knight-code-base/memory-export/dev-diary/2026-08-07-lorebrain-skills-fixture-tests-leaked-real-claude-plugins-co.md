# lorebrain skills-fixture tests leaked real ~/.claude/plugins content

test/cli.test.ts and test/graph.test.ts both asserted a 2-file skills fixture indexed to exactly 2 files. Both were getting 17 on this machine.  Root cause: indexSkills()/discoverAgents() in lorebrain/src/skills.ts resolve plugin content from opts.pluginRoot ?? process.env.LOREBRAIN_PLUGIN_ROOT ?? homedir()/.claude/plugins, independent of which root's skills graph is being built. commit 7ab8eaf added this plugin walk (Aug 4) so any lookup would see plugin-shipped skills/agents/commands. Neither test isolated it: graph.test.ts's indexSkills() call passed userSkillsDir but no pluginRoot, and cli.test.ts's spawned-subprocess env set LOREBRAIN_HOME and LOREBRAIN_USER_SKILLS but never LOREBRAIN_PLUGIN_ROOT. Both leaked whatever plugins are actually installed on the machine running the suite into what was supposed to be a hermetic fixture graph, a real ~/.claude/plugins/installed_plugins.json on this machine. Confirmed directly: re-running indexSkills against the same fixture with pluginRoot overridden to a nonexistent path returned 2; without the override, 17.  commit 92167a2 (Aug 5, the day after) claimed the suite was green with 137 passing, 0 failing, but did not touch either test file, so that claim likely predates enough plugin installs on this machine to trip the leak, or was verified in an environment with fewer/no plugins installed at the time. Either way, the assertion was never actually hermetic from the moment 7ab8eaf landed.  Fix: pointed both tests at empty/nonexistent plugin roots the same way they already isolated userSkillsDir, discoverPluginInstalls() returns [] on ENOENT by design, so this is the intended isolation mechanism, not a workaround. graph.test.ts now passes pluginRoot: path.join(PROJ, 'no-such-dir') alongside its existing userSkillsDir override. cli.test.ts now creates a third mkdtemp dir (emptyPlugins) and sets LOREBRAIN_PLUGIN_ROOT in the spawned subprocess's env, cleaned up in afterAll like the other two. No assertion numbers were changed, both still say filesIndexed).toBe(2), and both pass now. Full suite: 87/87.
