# Loremaster's standing-knowledge.md bounded to one pass entry, plus a second hygiene-gate collision closed

Continuation of the Obsidian protocol rework earlier the same day. Chris asked what from that fix would transfer to loremaster's Wake-Up/Goodnight protocol before doing the work, a useful check: the two protocols turned out not to be structurally identical. Protocol Obsidian.md mandated reading its whole history file in full on every activation; loremaster's Wake-Up Step 1 already stated a narrower intent, read only NEXT SESSION PRIORITY plus the single most recent pass entry from standing-knowledge.md. That distinction mattered enough to verify before assuming the same fix applied unchanged.  Verified anyway, and the problem was real: standing-knowledge.md was 1391 lines, denser prose than Protocol Obsidian.md's checkpoints (the first 193 lines alone measured 74,670 tokens). Root cause: no tool can selectively read only "the top section plus the most recent block" from a file without knowing line numbers in advance, so a plain Read pays for the whole file's token cost regardless of how narrow the protocol's stated intent is. Wake-Up Step 5a compounded this further by re-reading the exact same file a second time later in the same protocol run, pure duplication independent of file size, removed as part of this pass.  Fix: extracted every "Completed, pass N" entry except the current one (pass forty-two) into a new archive file, Standing Knowledge Pass History Archive.md, preserving newest-first ordering to match the live file's own existing convention. Used Bash sed to extract the bulk of the content directly on disk rather than routing 1200+ lines through Read/Write, since the goal was a verbatim copy with no transformation, reading and re-emitting that much content through the model would have cost far more than the fix was meant to save. standing-knowledge.md now holds only the header, the permanent Core Fact callout, NEXT SESSION PRIORITY, and the current pass entry, 47 lines. Updated loremaster.md's Wake-Up Step 1 to describe the file as deliberately bounded with a pointer to the archive, removed Step 5a's redundant re-read, and changed Goodnight Step 2 to roll the outgoing pass entry into the top of the archive before writing the new one, so the live file never grows past one entry even temporarily. Retention window (keep only the latest pass vs. several) was a real design call, put to Chris directly via AskUserQuestion rather than assumed; he chose latest-only, matching what Step 1 already intended.  A second finding, not part of the plan going in: standing-knowledge.md's own thirty-ninth pass entry (dated 2026-08-02) already documented the same class of hygiene-gate bug fixed earlier this same day, "found, not yet acted on... flagged here for a future session to actually fix." That entry described the italic case specifically (standing-knowledge.md opens every pass with a single-asterisk italic line, "*Last updated: pass forty-one...*"), a different collision than the bold-markdown case found independently while reworking Protocol Obsidian.md. The first fix (excluding `**` via a negative lookahead) didn't cover this, since a leading `*` directly against a word (italic) still matched. Corrected by requiring whitespace or end-of-line immediately after the leading asterisk (`\*(?=\s|$)`), which is the actual shape of a real code-comment continuation line and excludes both the bold and italic Markdown cases in one rule. A short resolution note was added to the archive file's own header so anyone reading the thirty-ninth pass entry later sees it was closed, rather than leaving it read as still-open history.  Two other files, Protocol Obsidian.md and Obsidian Shipped and Roadmaps.md, showed real uncommitted changes discovered while checking git status before committing this work, an Anchor Flow settings tab and auto-convert-on-paste feature, built in Chris's own verification session, not part of this pass. Confirmed the Session Resume block for Anchor Flow was updated in place rather than appended, direct evidence the bounded-snapshot design from the earlier fix is already working as intended in real use. Left those two files out of this session's own commit since the work is not this session's to claim.
