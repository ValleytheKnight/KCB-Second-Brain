# Scryptable Task 1 complete: app shell scaffold built, tested, and committed

Chris approved starting real implementation via the coordinator ("Chris approved. Start Task 1 (app shell scaffold) now."). This is the first real Scryptable code, following a full planning pipeline (CEO/design/eng/security/task-breakdown) completed 2026-08-14.  Built directly against the approved vault design record only, never opening whisper_app_design.pen (banned outright for .pen files, and the standing mockup-sourcing rule anyway): 02 Design/README.md and the Design Review doc's Window chrome, Navigation architecture, and Terminology sections. Caught and corrected one real staleness issue in the process: the Design Review doc's own Window Chrome section still named the fifth menu "Episode" with items like "Mark Episode Complete," predating that same review's later Terminology section, which settled on "Recording" as the default term (decision 0bd4977e). Built a shared terminology.py module (SINGULAR/PLURAL constants) so every menu label and empty-state string reads from one place, ready for the later customizable-term Preferences setting (Task 3) to retarget without touching UI code.  Shell pieces: TitleBar (frameless window drag, minimize/maximize/close), a QMenuBar built via chrome.py matching the recorded File/Edit/View/Recording/Help structure, a QToolBar (Import/Export/Send to Obsidian, Theme/Help pushed right), NavRail (Recordings/File Explorer as an exclusive checkable group switching SidebarPanel; a separate non-exclusive Preferences launcher button that always opens a tab rather than holding checked state, since the design record treats Preferences as a full screen, not a sidebar section), TabStrip (QTabWidget, closable, reuses an existing tab by key rather than duplicating), and EmptyStateWidget (the zero-recordings "Fresh Open" state). Light/dark palettes in theme.py, generated into one QSS stylesheet.  Real gap surfaced, not silently filled: the design record only ever describes the background as "warm cream," no exact hex is decision-logged or exported to a vault record anywhere. Rather than opening the mockup file to read the real value (doubly banned: .pen files can't be Read/Grepped at all, and even if they could, pulling a concrete token straight from a mockup violates the project's own standing rule), theme.py ships a placeholder neutral palette, explicitly flagged in its own module docstring and in the Task Breakdown's status line, as an open item pending a real decision.  Verification: wrote tests/test_app_shell.py (pytest-qt, 6 tests covering empty-state launch, minimum size, nav rail/sidebar switching, and Preferences tab open/reuse/close), ran headlessly (QT_QPA_PLATFORM=offscreen), all 6 passed. Followed with a real, non-pytest launch/interaction check (a plain python -c script instantiating QApplication and MainWindow directly) to confirm the app actually launches, opens and closes a real tab, and returns to the empty state correctly outside the test runner too.  One real bug caught before commit: a draft line in main_window.py wired the nav-rail signal with a stray `self._sidebar.show_section if False else self._show_sidebar_section` ternary, leftover noise from restructuring while drafting. It happened to be harmless (Python never evaluates the False branch, so the not-yet-created self._sidebar was never actually touched), but was confusing and would have broken immediately had the branches been reversed. Found by re-reading the file before running tests, not by the tests themselves. Fixed to a plain single connect call. Logged in Task 1 App Shell Build Notes.md as a real lesson: re-read touched files before running tests, not only before committing.  Committed locally: a421cab, "Add Task 1: app shell scaffold."
