# Obsidian Kanban silently drops and then deletes any card written below the settings block

Found during a bare "activate devknight" orientation sweep of the DevKnight Workshop vault. Two of KnightOS's three kanban boards had their `%% kanban:settings` block sitting mid-file, with completed-task cards written in below it.  Mechanism, verified against the plugin's own bundled parser at `.obsidian/plugins/obsidian-kanban/main.js` rather than assumed. The board builder (minified `B_`) iterates the markdown AST, and for each `##` lane heading it walks forward looking for the first `list` node. Its scan predicate returns false on two things: another heading, and any paragraph whose text starts with `%% kanban:settings`. So a lane binds to the first card list it finds and the walk stops dead at the settings block. Anything past that block never enters the parsed board model at all.  Observed effect: Milestone 1 Kanban rendered as though Done stopped at Task 6, hiding Tasks 7, 8, 9, 10 and two ad hoc cards. Project Tabs Kanban rendered as though Done stopped at Task B, hiding Tasks C, D, E.  The part that makes this more than a display bug: the serializer (minified `vk`) rebuilds the file from the parsed model and re-appends the settings block at the end. Since the stranded cards were never in the model, the first ordinary UI interaction with either board (dragging a card, ticking a checkbox, adding a card) would have rewritten the file without them. Real data loss, triggered by normal use, with no warning.  Root cause of how it got there: an earlier repair session was fixing genuine kanban staleness and appended the missing cards to the end of the file instead of inserting them into the target lane's existing list. Its own record says the cards were added, and they literally were, so the repair read as complete and never reached the board. This is a second-order failure of the same recurring problem decision `4dfdf041` diagnosed.  Repair: backups first, then a programmatic rewrite that lifts the settings block out of the middle, rebuilds each Done lane as one contiguous list, and re-appends the block at the end. Two loose paragraphs that had never been list items became real cards so they render rather than staying invisible. Verified two independent ways: the settings block is the last content in both files, and a word-multiset diff against the backups confirmed zero words lost (the only additions were the two `- [ ]` markers).  Durable rule, logged separately via learnings_log: when editing an Obsidian Kanban board by direct file write, insert cards inside the lane's existing contiguous list, and verify the repair by checking the settings block's position, not merely that the card text exists somewhere in the file. Also note a blank line between two card lines splits one list into two, and only the first is read, so a "contiguous list" requirement is literal.
