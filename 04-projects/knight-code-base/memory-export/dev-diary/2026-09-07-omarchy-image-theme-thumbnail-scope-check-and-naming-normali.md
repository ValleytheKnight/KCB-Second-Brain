Checked decision_search for "thumbnail" and "screenshot" (both empty, after first mistakenly passing all:true which returned every decision regardless of query and had to be redone properly), dev_diary_search "thumbnail" (empty), and grepped the full CEO plan and CEO review doc for thumbnail/screenshot/picker. Logged as decision 9775f8b0, flagged that this needs to go back through CEO review (real mechanism and effort call, since screenshotting a live multi-window desktop is materially heavier than the already-accepted approach) before Design Review can incorporate it.  2. Theme-name normalization, silent backend vs. live UI enforcement. First pass used the wrong source: inferred the direction from /usr/bin/omarchy-theme-set's THEME_NAME line (lowercase + spaces-to-dashes) since the actual reused wrapper script wasn't found by an initial `find` pass. Coordinator corrected with the real file, ~/.local/bin/omarchy-theme-from-image (the exact script CEO review names as reused theme-folder-write logic), verified directly by reading it: NAME=$(echo "$RAW_NAME" | tr '[:upper:]' '[:lower:]' | tr ' ' '-'), with its own comment explaining Omarchy's picker derives a "Title Case With Spaces" display from this exact lowercase-dash directory name at render time. Same direction I'd already found via omarchy-theme-set, now confirmed at the source Chris was actually asking about. This was never an open decision, already implemented; the mockup and plan language just hadn't reflected it. Fixed on canvas: Collision Guard modal (ps2HX) rename field now shows an unmodified human-typed value ("Autumn Hearth 2", proving no live input reformatting) plus two small derived-preview lines added to the Rename Section, styled as a live-computed readout (small corner-down-right icon + $font-heading value) rather than a prose caption: "Stored as: autumn-hearth-2" (this app's real behavior) and, kept clearly separate per the coordinator's explicit instruction not to conflate the two, "Omarchy's picker shows it as: Autumn Hearth 2" (Omarchy's own downstream display, not something this app produces).  Real lesson from this pass: the first naming-normalization answer was directionally right but sourced from the wrong file (a plausible nearby script, not the one actually named in the CEO review). Getting the right conclusion from an unconfirmed source is still a gap; verify_dont_guess means finding and reading the specific file named as authoritative, not a lookalike that happens to agree.
