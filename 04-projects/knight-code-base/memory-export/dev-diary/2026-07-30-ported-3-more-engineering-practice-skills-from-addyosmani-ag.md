# Ported 3 more engineering-practice skills from addyosmani/agent-skills, closing confirmed capability gaps

Second batch from github.com/addyosmani/agent-skills, following the pattern the first 7-skill port established. Each of the three filled a gap that had been verified against actual Knight Code content rather than inferred from skill titles.  frontend-ui-engineering (preamble tier 1, reference knowledge): the accessibility layer nothing else here covered. impeccable and knightcode-emil-design-eng are taste and craft skills; neither carries WCAG 2.1 AA requirements, keyboard-operability rules, focus-management contracts, ARIA naming, live regions, or a state-placement decision list. Adapted beyond the source: added an accessible-name section, three focus rules (trap on open, restore on close, never remove the indicator), a live-region section for announcing async change, reduced-motion handling, and 200% zoom to the responsive checks. Retargeted its dangling references/accessibility-checklist.md pointer into a Related Skills block that hands taste work to knightcode-frontend-design and impeccable, motion to knightcode-apple-design and knightcode-emil-design-eng, and runtime verification to knightcode-browse and knightcode-qa.  security-and-hardening (tier 1, reference knowledge): knightcode-cso audits and refuses to write code, so there was no build-time reference with runnable prevention patterns. Kept the source's real substance (STRIDE pass, three-tier boundary system, OWASP Top 10 patterns, the SSRF allowlist with its TOCTOU caveat, supply-chain script-blocking order, the LLM output-handling section mapped to the 2025 OWASP LLM Top 10) and made the cso relationship explicit in both directions. Added Knight-Code-specific framing: credentials live under ~/.knightcode/ outside the tracked repo, deferred vulnerability fixes get a decision_log entry rather than a code comment, field allowlists over denylists with the reason, and a rationalization row for "it's a personal single-user tool" answered by the untrusted content it reads (web pages, transcripts, vault notes, dependency scripts). Removed all three references/security-checklist.md pointers; the checklist content was already inline.  planning-and-task-breakdown (tier 2, real work loop): the actual gap was decomposition. knightcode-autoplan and the three plan-review skills all grade a plan that already exists; none turns a fresh spec into ordered, sized tasks. Kept the dependency graph, vertical-vs-horizontal slicing, XS-to-XL sizing table, and checkpoint discipline. Adapted the read-only step to use knightbrain_* and lorebrain_* lookups plus decision_search, promise_search, and learnings_search before planning around anything already settled, added a plan-approval step that logs architecture decisions with decision_log, and noted that two tasks editing the same files aren't parallel whatever the graph says. Removed the references/definition-of-done.md pointer and the /build command dependency, which has no Knight Code equivalent; retargeted execution to knightcode-incremental-implementation. Kept tasks/plan.md and tasks/todo.md as the output convention but stated plainly that those are per-feature working files, distinct from the repo-root TODOS.md.  Deliberately not wired into devknight: none of the three is native-Windows-specific. frontend-ui-engineering is the only one with genuinely web-bound code (ARIA attributes, CSS media queries, DOM focus), and both CLAUDE.md and SKILL-CATALOG.md now say so honestly rather than claiming full platform neutrality for it, while noting its rules map onto WinUI3's automation-peer and focus model.  Hygiene: stripped every em dash the source carried, checked all three templates against the full banned-word list with word-boundary matching, and confirmed no dangling references/*.md pointers survive in the generated output.
