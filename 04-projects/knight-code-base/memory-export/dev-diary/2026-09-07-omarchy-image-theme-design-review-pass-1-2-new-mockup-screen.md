# omarchy-image-theme: design review pass 1 + 2 new mockup screens

Ran the formal 7-pass design review against the 7 mockups already on the Pencil canvas (Pen Designs/omarchy-image-app.pen: HEVbu, dIAJE, u44VL1, NvvpS, E50mj6, dFXN0, oy3rJ). Pulled real structural data via pencil execute/Get rather than reasoning from memory. Then built the two missing accepted-scope states: Save Conflict - Collision Guard (ps2HX) and Generate - Batch Progress State (t9hNa), both reusing the exact design tokens ($bg/$surface/$surface-2/$accent/$accent-foreground/$text-primary/$text-secondary/$error/$warning/$success/$border/$font-heading/$font-body) and component patterns (Top Nav, buttons, chips, progress track/fill, icon badges) already established on canvas, per decision 04ffa5cd's visual direction.  Full pass findings below.  PASS 1, Information architecture. Consistent 2-shell pattern across all 7: Top Nav (Brand + Generate/Edit Mode Tabs) is present on every screen, Sidebar+Main 2-column layout only appears once content exists (Happy Path, Loaded), collapses to a single centered Body for pre-content states (Empty, Loading, Error, Selection). This is a coherent, deliberate IA, not accidental. No finding requiring a fix.  PASS 2, State coverage. Generate flow: empty/loading/success/error, all present. Edit flow: selection/loaded/error, all present, deliberately no loading state (near-instant per decision 04ffa5cd's session notes). Two CEO-review-accepted scope items (5fa42199 collision guard, 44e3b1b0 batch mode) had zero screens before this pass; both now built. No dedicated "batch selecting files" pre-run screen was added, only progress/summary, since Generate's existing empty-state Drop Zone already carries the "Batch process a folder instead" entry link (confirmed present on both dIAJE and NvvpS via Get) and a folder picker is an OS-native dialog, not an app screen to mock.  PASS 3, User journey. Both flows' branches (success/error) are reachable and visually distinct. One real gap found and NOT fixed (flagging for Chris/eng, not a mockup change): no post-Save confirmation state exists anywhere, neither Happy Path nor Loaded shows what happens immediately after a successful Save click (toast? redirect? disabled button?). This is a real unresolved decision, not just a missing mock.  PASS 4, AI-slop check. Checked against the pen-dev skill's own anti-patterns (box-in-box overuse, repetitive grids). Card/strip/badge wrapping throughout is functional (theme selector cards need a name+badge+swatch-strip; each swatch needs its own hex label), not decorative. Selection screen's 6 theme cards intentionally show a lightweight 5-chip strip rather than repeating the full 18-swatch palette per card, avoiding a repetitive-grid trap. No finding.  PASS 5, Design-system alignment. Strong: all fills/fonts route through named variables everywhere except a few literal per-screen hex values (History Swatch chips, terminal Output Line text colors, theme-card Chip fills) which is correct, since those ARE the generated/theme-specific data, not chrome. Two real problems found: (a) Error Banner width is 560px on both Generate screens (dIAJE, NvvpS) but 640px on Edit's error screen (oy3rJ) - same component, same purpose, unexplained size drift. (b) History Section: Undo button label reads "Undo (3)" but the History Strip actually renders 5 swatch chips (HEVbu and dFXN0 both, confirmed via Get). Either the count label or the chip count is wrong; they must agree once wired to real data. Neither was silently fixed - both are canvas facts to confirm with Chris before build, since either could be the intended one.  PASS 6, Responsive/accessibility. All 7 screens plus the 2 new ones are fixed 1440x960, no breakpoints, which matches a native Tauri desktop app (not a resizable browser page) and is not a gap by itself, but should be an explicit, confirmed decision rather than assumed. Text sizing runs as small as 10px (swatch Hex labels) and 11px ($text-secondary section labels) - flag for a real contrast check against $surface/$bg once real color values are picked, not just eyeballed in Pencil. Icon-only controls (Dismiss, Back Link chevron, Change Image) need real accessible labels when built, not carried over from the mock as bare icons.  PASS 7, Unresolved decisions carried forward to eng/task-breakdown, not resolved here: post-save confirmation UX (Pass 3), Error Banner width (Pass 5a), Undo count vs strip count (Pass 5b), terminal live-preview color binding (Output Line colors are currently hardcoded per screen rather than derived from the actual generated palette array - fine for a static mock, must be dynamic in the real build), and whether Reset (on Loaded/Happy Path) reverts to the original generated palette or the last-saved state.  New screens built, both starting from the same Top Nav/token patterns pulled directly off the existing canvas nodes (via Get), not invented: - Save Conflict - Collision Guard (ps2HX): centered modal over Body, warning-toned (not the $error red used for hard failures) icon badge, shows the colliding theme's real existing swatch strip, an inline rename field pre-filled with a suggested alternate name, and 3 actions ordered Cancel / Overwrite Existing (outlined-danger, de-emphasized) / Save as New Name (primary, accent-filled) so the safe path is visually default. - Generate - Batch Progress State (t9hNa): overall progress bar, a 6-row list card mixing done/processing/failed/queued rows in one view (matches the CEO review's sequential-processing, no-single-failure-blocks-batch foundational decision), a failed row that reuses the exact real wallust .heic error text already established on NvvpS, and a tri-color tally (done/failed/remaining) plus a Cancel Batch / disabled-styled View Results footer.  Both new frames used placeholder:true during construction, unset on completion, per the pen-dev skill's own convention.
