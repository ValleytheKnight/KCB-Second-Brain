# Scryptable vault-currency pass: launcher/translucent fix, HF gate finding, Task 7 end-to-end verification closed

Updated the DevKnight Workshop vault's Scryptable project notes with three real, confirmed items from work that happened after the last vault sync (overnight Task 7 build plus same-morning follow-on).  1. Launcher and translucent-window background fix, commit 6ea4761 (pushed to origin/master): run.bat called `python` directly, which resolves to the Windows Store alias stub on this machine rather than the real interpreter, so the desktop shortcut silently opened nothing; fixed with `py -3`. Separately, FirstRunWizard and MainWindow both set Qt.WA_TranslucentBackground for their rounded frameless chrome, expecting QSS to paint the background; on Windows that combination renders the window fully transparent instead. Fixed with WA_StyledBackground plus a real paintEvent on both that paints an opaque rounded rect directly with QPainter.  2. HuggingFace token confirmed working (keyring, service "Scryptable", username "huggingface_token"), and a real non-obvious gating dependency found: pyannote/speaker-diarization-3.1 internally pulls a PLDA component from the separately-gated pyannote/speaker-diarization-community-1 repo, so accepting the license only on the selected model variant is not enough, the community-1 gate must also be accepted.  3. Task 7's diarization pipeline verified end-to-end against real audio for the first time: diarization.run_diarization() run directly (no GUI, no Craig import) against a real Discord recording clip on disk (hulgot_loop_test.flac, an existing fixture from the Protocol Whisper project). Real success, 16 segments correctly split across two speakers.
