# codemode work uncovered plaintext Obsidian keys and a broken vault port, both fixed

While building codemode (spec: specs/20260824-codemode-mcp-call-batching.md, issue #2), code review flagged three Obsidian Local REST API keys committed in plaintext in .mcp.json at commit 133b434 (pre-dating this feature, from an earlier "commit all").  Fix, in order: 1. Rotated all three keys at the source: regenerated in each vault's Local REST API plugin data.json (felled_god, devknight, plugin_tester). Old keys are dead. 2. New keys moved to ~/.knightcode/secrets/obsidian.env (chmod 600, outside the tracked repo), sourced from both ~/.zshrc and ~/.config/fish/config.fish since this account's $SHELL (zsh) and /etc/passwd login shell (fish) disagree. 3. .mcp.json rewritten to reference Claude Code's own supported ${VAR} expansion syntax (${OBSIDIAN_API_KEY_FELLED_GOD} etc) instead of plaintext values. 4. codemode/src/mcp-config.ts got the same ${VAR}/${VAR:-default} expansion added, since codemode's daemon spawns these servers independently of Claude Code's own MCP loader and would otherwise pass the literal unexpanded string to a spawned server. 5. History cleanup: used git filter-repo (installed via pipx, no sudo needed) to purge the three old key strings from every commit and blob, force-pushed, then verified against a fresh gh-cloned copy of the GitHub repo, zero matches anywhere in history.  Separately found while rotating: the Plugin Tester vault's Local REST API plugin had its HTTPS "port" field set to a broken value (271, not a real port), while .mcp.json expected 27130. mcp-obsidian connects over HTTPS (confirmed via an HTTPSConnectionPool error on a live connection attempt), so the fix was correcting the vault's "port" field (not "insecurePort") to 27130, matching the pattern already used by the other two vaults where .mcp.json's OBSIDIAN_PORT matches the HTTPS port field exactly.  Obsidian wasn't running at rotation time (connection refused on all three ports), so nothing live broke; the new keys and port are what each vault picks up on next launch.
