# "simplify" was a Claude Code built-in, not a Knight Code skill; ported a real one

A prior research agent this session could not find tracked source for a "simplify" skill and suspected Knight Code was relying on an unowned built-in. Investigated and confirmed both halves of that suspicion, plus corrected one part of the premise.  What "simplify" actually was: a Claude Code built-in skill compiled into the CLI binary itself. The skill's own description string ("Review the changed code for reuse, simplification, efficiency, and altitude cleanups... use /code-review for that") is present inside ~/AppData/Roaming/npm/node_modules/@anthropic-ai/claude-code/bin/claude.exe. It is not a plugin: ~/.claude/plugins/installed_plugins.json lists only winui@win-dev-skills, and the plugins cache holds only win-dev-skills and claude-plugins-official/discord. There was no simplify/ directory in the repo and no ~/.claude/skills/simplify or knightcode-simplify install.  Correction to the premise: Knight Code's own docs never referenced it. A case-insensitive scan of every markdown file found zero "simplify" skill references in CLAUDE.md, SKILL-CATALOG.md, or TODOS.md. The only near-match was SKILL-CATALOG's impeccable `distill` row, whose description reads "Strips unnecessary complexity, simplifies." So the routing table was never wrong; the built-in was simply visible in the live skill list and got mistaken for an owned entry.  The fix: ported addyosmani/agent-skills `code-simplification` as an eleventh skill from that repo, named `simplify` to match Knight Code's own naming and to give the concept a genuinely owned home. Tracked source at simplify/SKILL.md.tmpl (preamble-tier 1, matching the rest of that batch), generated simplify/SKILL.md via gen:skill-docs, installed copy at ~/.claude/skills/knightcode-simplify/. Retargeted the upstream content: dropped its inline credit to an external plugin path that does not resolve from here, replaced the cross-reference to code-review-and-quality with knightcode-review and knightcode-investigate, added a Related Skills section, wired in knightbrain_def/_callers/_refs as the structural way to answer "what calls this" before deleting anything, and folded the no-history-comments rule into the comment-pattern table so a simplification pass routes narrative comments to dev_diary_log instead of leaving them. Rewrote every em dash and checked the result against scripts/banned-language.json: clean on both the template and the generated file.  Also fixed real count drift left by the two earlier ports this session: CLAUDE.md and TODOS.md said 40 ported skills with 10 from addyosmani while the catalog section header said "Ten of the source repo's 24." All now read 41 and eleven, and the catalog has a row for the new skill.
