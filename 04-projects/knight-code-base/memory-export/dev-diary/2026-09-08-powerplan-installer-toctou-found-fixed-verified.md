# powerplan installer TOCTOU: found, fixed, verified

HANCORE-linux reviewed omarchy-powerplan at commit f3f61f1 (omacom/omarchy-plugin-marketplace#5402) and flagged that README's `sudo install -D ... ~/.config/omarchy/plugins/valleytheknight.powerplan/powerplan-configure-hibernate /usr/local/libexec/...` reads the source from a user-writable checkout after the sudo auth delay, letting a local process swap the file and get arbitrary bytes installed as a root-owned executable that pkexec later invokes.  Fix: scripts/install-privileged-helper. Opens the source with O_NOFOLLOW, checks S_ISREG and no group/other write bits, checks ownership is root or the invoking user (via SUDO_UID), hashes against a hard-coded EXPECTED_SHA256 of the reviewed release, copies into an O_CREAT|O_EXCL staging file, re-verifies the digest post-copy, then os.replace atomically. README's install block now calls this instead of raw `sudo install`.  First pass had a real bug: the digest-mismatch and other abort paths call a `fail()` helper that raises SystemExit, which does not subclass Exception. The staging cleanup was written as `except Exception: staging.unlink(); raise`, so a post-copy digest mismatch would leave the staging file behind, exactly the "remove any marker on mismatch" case the reviewer asked for. Changed to `except BaseException`. Also added the ownership check, which the first draft omitted despite the reviewer explicitly asking for "safe ownership/mode."  Verified without touching real system paths or requiring sudo: patched a scratch copy to skip the root check and point DEST into the scratchpad dir, then confirmed (1) a tampered source is rejected on digest mismatch with no staging file left behind, (2) a symlinked source is rejected with ENOSYS/ELOOP-style symlink error under O_NOFOLLOW, (3) with SUDO_UID set to simulate real sudo, a tampered source still gets caught by the digest check, and a chown PermissionError (expected outside real root) still triggers cleanup with no staging leftover, confirming the except BaseException fix actually works.  Also added .github/workflows/verify-helper-digest.yml: fails CI if EXPECTED_SHA256 in the installer doesn't match sha256sum of powerplan-configure-hibernate, so a forgotten manual digest bump is caught at PR time. Considered and rejected CI-auto-commit, GPG signing, and signed-package distribution as too heavy for a single-file personal plugin at this scale.  Not yet committed, pushed, or replied to on the PR thread; Chris to review and decide when to ship.
