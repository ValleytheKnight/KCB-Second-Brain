# Scryptable Task 3 complete: first-run setup wizard built, tested, and committed after three cleanup rounds

Chris approved moving forward on Task 3 via the coordinator. Full orientation ran first this session: the Continuation Point, Task Breakdown's Task 3 entry, the Design folder README, and a decision_search pass, per this project's standing rule.  Built the two-question chromeless wizard (workspace folder, unit-of-work term) matching the design review's chromeless call, decision 08b7e3ec. New app_config.py persists both answers to a per-user config.json via Qt's own QStandardPaths.AppConfigLocation, following workspace_state.py's rebuild-on-corruption pattern, a missing, corrupt, or unrecognized-schema config file falls back to defaults rather than blocking launch. terminology.py gained an apply(singular) function so the customizable term (decision 0bd4977e) can change the module's SINGULAR/PLURAL constants at runtime. main.py now checks for a first-run condition, shows the wizard when needed, and reopens the last workspace automatically on a returning launch.  Moved the kanban card to In Progress before writing any code, per the standing lane-timing rule.  Ran the simplify skill (4 parallel review angles: reuse, simplification, efficiency, altitude) against the original commit and applied the real findings: removed a double config.json disk-read after the wizard accepts (the wizard now exposes self.config, main.py reads it directly instead of re-reading the file it just wrote), unified the terminology apply call to a single call site instead of splitting it across two code paths, derived the module-level SINGULAR/PLURAL by calling apply once at import time instead of duplicating the pluralization rule, and extracted a shared choose_folder helper into a new dialogs.py to remove a duplicated QFileDialog call between the new wizard and main_window.py's existing request_open_workspace.  A follow-up code-review pass on that same diff caught a real regression the efficiency fix had introduced: deferring the workspace scan past window.show() caused a visible empty-state-then-populate flash on every returning-user launch. Reverted back to scanning before show(), matching Task 2's own existing precedent.  The same code-review pass also flagged FirstRunWizard.workspace_root() as carrying a divergence risk between two fields once production code stopped reading one of them. Fixed at the time by deriving workspace_root() from the config object when set. A second, independent simplify round on that exact fix disagreed: both the simplification and altitude agents pointed out the derived branch did not actually add real protection, since the finish method sets both fields from the same source in the same call, so they cannot currently diverge regardless of which field the accessor trusts. Reverted to a single plain field return, and deduplicated three tests' identical setup into a shared pytest fixture. A third, final code-review pass on that revert caught one last stale test name, renamed to match what it actually verifies. Full detail on this three-round back-and-forth, including the real lesson that two independent review agents gave opposite advice about the same two-line accessor and the correct call only became clear by tracing the actual control flow rather than trusting either review's framing, logged at Projects/Scryptable/06 Lessons Learned/Task 3 First-Run Setup Build Notes.md in the vault.
