# Knight Code's own browse binary is broken too, same daemon as the ported plugin skill, root cause is a missing playwright package not just sharp/detect-libc

Follow-up to today's two earlier browse-skill entries (sharp/detect-libc mismatch, then daemon-fails-to-restart). Chris clarified mid-investigation that the binary at `C:\Users\Chris Brown\.claude\skills\knight-code\browse\dist\browse` (referenced by the `knightcode-browse` skill, `C:\Users\Chris Brown\.claude\skills\knightcode-browse\SKILL.md`) is Knight Code's own separately-built browse tool, the one Knight Code should default to going forward, not a rebrand of the externally-derived plugin skill. Checked it directly rather than assuming it was unaffected.  It is affected, and currently non-functional. Verified end to end: - SETUP check from the skill's own SKILL.md resolves the binary: `READY: /c/Users/Chris Brown/.claude/skills/knight-code/browse/dist/browse` (the `.exe`-less path resolves via Git Bash's executable test against `browse.exe`). - `browse status`, `browse goto https://example.com`, and `browse screenshot` all fail identically: `[browse] Starting server...` then `[browse] Server failed to start within 15s`, exit code 1. No screenshot file produced. - Ran `server-node.mjs` directly with `node` (v24.18.0) from `browse/dist/` to see the real startup error the wrapper swallows: `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'playwright' imported from .../browse/dist/server-node.mjs`. - `node_modules` under `C:\Users\Chris Brown\.claude\skills\knight-code\` currently contains only `detect-libc` (v1.0.3) plus two empty scope folders, `@img` (sharp's platform binaries normally live here) and `@ngrok`. `playwright` itself, not just `sharp`, is now completely absent. `sharp` is also fully gone, not merely version-mismatched as the first entry described. - This is a new, more severe finding than the earlier two entries: the daemon isn't failing because of the sharp/detect-libc mismatch reported first, it's failing because `playwright` (a real top-level `import` at module-load time in `server-node.mjs`, not the lazy dynamic `import("sharp")` used for the screenshot-size-guard) is missing entirely, so the server process crashes immediately on every single startup attempt. The earlier blind `npm install <pkg> --no-save` calls in this same directory (no real `package.json`, only a near-empty `package-lock.json` with `"packages": {}`) most likely got npm to prune `playwright` and `sharp` as extraneous during one of those installs, since npm treats anything not declared in a project's own `package.json` as removable. - No `setup` script exists in this skill directory (`browse/setup`, `./setup`, or similar), despite the skill's own SETUP section instructing `cd <SKILL_DIR> && ./setup` as the self-heal path when the binary is missing. That path is currently a dead end here too.  Did not attempt any further installs or fixes, per explicit instruction: this directory's `node_modules` has now absorbed three blind-fix attempts across two entries and this one would be a fourth. Real fix needs Chris's direction: either a real `package.json`/lockfile for this directory that pins the exact `playwright`/`sharp`/`detect-libc` versions the prebuilt `browse.exe`/`server-node.mjs` bundle expects (then a clean `npm install` against that), or a full re-vendor of this skill's `node_modules` from whatever built `browse.exe` originally.
