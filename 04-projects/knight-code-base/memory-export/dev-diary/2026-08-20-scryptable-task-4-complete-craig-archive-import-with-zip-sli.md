Built craig_import.py (plan_craig_extraction/extract_craig_archive, entry-level zip-slip containment check via a shared is_within_directory helper), archive_watcher.py (QFileSystemWatcher-based scan-and-diff for new *.zip files in the workspace root), ui/toast.py (New Recording Detected, Set Up/Ignore, no auto-dismiss matching the design review's own critique finding), and ui/new_recording_setup.py (editable name field, live preview built from the same plan the eventual write uses, disabled Continue on any containment failure). Ran this project's standing hygiene pass before commit: two parallel code-review sub-agents (Standards axis, Spec axis) against the diff to origin/master. Standards axis found one real hard violation (a decision-ID citation in craig_import.py's module docstring, a dev-diary/history-comment violation), fixed immediately. Spec axis found a real, exploitable gap beyond the letter of Task 4's acceptance criterion: the criterion only requires zip entries to stay contained within the target directory, but the target directory itself is built from a user-editable recording name in New Recording Setup, and that path was never validated against the workspace root. A name like "../../elsewhere" moved the write target outside the workspace before a single zip entry was even inspected, and every entry in a perfectly well-formed archive would then pass the entry-level check relative to that already-escaped target. Verified the claim directly by reading the actual control flow (not trusted on the review's framing alone), confirmed real via the OS's own path resolution at mkdir/write time. Fixed with a second is_within_directory check on the candidate target directory before plan_craig_extraction is ever called, plus an independent defense-in-depth check at the actual write call site in MainWindow, and moved the dialog's Continue-enable to fire only after the full preview loop succeeds rather than before it.  A second real finding came from the real, non-pytest launch/interaction smoke script (this project's standing practice alongside pytest, not a replacement for it): NewRecordingSetupDialog compared resolved plan paths against an unresolved workspace_root, which worked fine against pytest's already-canonical tmp_path fixture but broke on a real launch, this machine's own %TEMP% resolves to a short 8.3-form path that .resolve() normalizes back to long form, so relative_to() raised ValueError on a real import through a real temp workspace. Fixed by resolving workspace_root once in the dialog's own __init__.  53/53 pytest-qt tests pass (5 new test files: test_craig_import.py, test_archive_watcher.py, test_new_recording_setup.py, test_toast.py, test_craig_import_flow.py).
