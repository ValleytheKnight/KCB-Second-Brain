# Scryptable repo created (empty), formal-dev-workflow gate blocked even README/.gitignore writes

Created Documents\DevPrograms\Scryptable\ (git init, branch master) and a private GitHub repo at https://github.com/ValleytheKnight/Scryptable under the ValleytheKnight account, remote "origin" wired. No name collision (gh repo view returned not-found before creating).  Real finding: attempting to write README.md and .gitignore into the new repo (via the Write tool) was blocked by hosts/claude/hooks/formal-workflow-gate.ts with "Formal dev workflow in progress for feature protocol-whisper-app, phase eng. Edits to application source are blocked until planning phases complete." This happened even though the target files live in a brand-new, unrelated repo outside Knight Code's own tree, not inside Knight Code itself, confirming the gate's scope is the active session/workflow state, not the target file's own repo. It also confirmed active.json had already been restored from active.json.parked-by-security-task to {"feature": "protocol-whisper-app"} (the parked file and the leftover hookselftest.json are both gone now), so un-parking had already happened before this dispatch resumed, not something this session had to do itself.  Left the repo as an empty shell rather than bypassing the gate (KNIGHTCODE_FORMAL_WORKFLOW_GATE=off is offered in the hook's own error message but was not used). A bare README and .gitignore are not application implementation in spirit, but the gate does not appear to distinguish scaffolding from real source, it blocks broadly once a feature is active and its phase is short of implementation/done. Worth a real decision later: either teach the gate to exempt non-code scaffolding (README, .gitignore, LICENSE) for a freshly created repo, or accept that repo content genuinely waits for task breakdown to complete, and say so explicitly rather than discover it by trial and error each time.
